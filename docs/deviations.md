# Deviations from Percona DEB / official image behaviour

Every departure from DEB build parity or from the official `percona/*` images is listed here
with its reason. A change that introduces a deviation adds its row here.

| Area | Official/DEB behaviour | Ours | Reason |
|------|------------------------|------|--------|
| V8 `gn` (v8 package) | `build_v8.sh` uses the gn binary pinned by V8 DEPS (`gn_version` git_revision 54f5b539, 2024-10) | Wolfi `gn` (0.0_git2026xxxx), unless `GN_BIN=buildtools/linux64/gn` is set in `packages/v8/melange.yaml.tmpl` | Spec §6 prefers Wolfi gn/ninja. Wolfi gn is ~2 years newer than V8 12.9's pin; compatibility is unverified until the first host build. Switching to the pinned binary (shipped in the vendored tree) is a one-line change. |
| V8 gn args (v8 package) | `build_v8.sh` args only | same args plus `use_glib=false` | Chromium's Linux default `use_glib=true` makes `gn gen` require glib-2.0/gmodule/gobject/gthread `.pc` files (first laptop build failed there); the standalone `v8_monolith` target never links glib, so not installing glib-dev into the build environment is the smaller change. Non-semantic for libv8_monolith.a. |
| V8 with GCC 16 (v8 package) | `build_v8.sh` on the build hosts' older GCC | the `cc_wrapper` script also adds `-include cstdint` to every C++ (`g++`) compile | Wolfi's GCC 16.2 libstdc++ no longer includes `<cstdint>` transitively and V8 12.9 headers use `uint8_t` without it (first laptop build: `src/objects/type-hints.h`). One forced include instead of patching each header; no behaviour change. |
| V8 abseil with GCC 16 (v8 package) | unpatched V8 tree | `packages/v8/patches/0001-absl-gcc16-hash-slot-fn-constexpr.patch`: the flat/node hash map policies return abseil's non-type-erased hash function instead of `nullptr`, and `hash_policy_traits::get_hash_slot_fn` no longer compares a function address with `nullptr` | GCC 16 rejects that comparison in a constant expression (`hash_policy_traits.h:163`, first laptop build; reproduced with a standalone GCC 16 compile, which the patch fixes). The same function is selected as before. |
| V8 sources (v8 package) | `build_v8.sh` clones depot_tools and syncs at build time | Source vendored once by `scripts/vendor-v8.sh` into a sha256-pinned tarball; only the `lastchange` hook is run | Offline, reproducible melange build. |
| V8 reproducibility flags (v8 package) | `build_v8.sh` has no path mapping | extra gn arg `cc_wrapper=<script>` that injects `-ffile-prefix-map=<build dir>=.` into every gcc/g++ call; `SOURCE_DATE_EPOCH` required/exported | Build-path-independent output. Non-semantic. Chromium's gcc toolchain ignores a gn `extra_cflags` arg, so the cc_wrapper prefix is the mechanism; __DATE__/__TIME__ are already blanked by Chromium's `compiler_deterministic` config. |
| OpenSSL (percona-server, percona-mysql-shell, percona-xtrabackup) | DEB: Debian's OpenSSL 3 (`libssl-dev`); official image: el9 OpenSSL 3 | `openssl-dev~3.6` (Wolfi OpenSSL 3.6.x); mysqld links `libssl.so.3`. Wolfi's libldap and libk5crypto (Kerberos) link OpenSSL 4 (`libssl.so.4`/`libcrypto.so.4`), so both load into mysqld when those libraries are used | Owner ruling 2026-11-15. Wolfi's default `openssl-dev` is OpenSSL 4.0; MySQL 9.7 supports OpenSSL 1.1/3.x only (CMake: "Not a supported openssl version"). The two coexist: distinct symbol versions (`OPENSSL_3.x` vs `OPENSSL_4.0.0`). Image test `server-plugins.bats` checks TLS with both loaded. Recipes assert the OpenSSL 3 headers. |
| curl (percona-server, percona-xtrabackup, percona-mysql-shell) | DEB: system `libcurl4-openssl-dev` | PS and PXB: `-DWITH_CURL=bundled` (`extra/curl`, curl 8.14.1, HTTP only); mysql-shell (no bundled option): the same `ps-src/extra/curl` sources built static (PIC, HTTP only, OpenSSL 3.6, no zlib/zstd/brotli) and passed as `-DWITH_CURL=<prefix>` | Wolfi's `curl-dev` requires the OpenSSL 4 headers (via `ngtcp2-dev`), which conflict with `openssl-dev~3.6` in the build environment. Bundled curl is what MySQL ships for this case and links our OpenSSL 3.6. |
| PS build tooling (percona-server) | DEB: `make -j$(NCPU)` (Unix Makefiles), dpkg build env | Ninja; links limited to 4 concurrent jobs by adding `link=4` to the `JOB_POOLS` property in `ps-src/CMakeLists.txt` (recipe `sed`, checked) and `-DCMAKE_JOB_POOL_LINK=link`; `-DCMAKE_POLICY_VERSION_MINIMUM=3.5`; ccache via a compiler launcher | Build scheduling / CMake 4.x compatibility only; output unchanged. `-DCMAKE_JOB_POOLS` cannot be used because MySQL's CMakeLists overwrites `JOB_POOLS`. |
| PS reproducibility flags (percona-server) | DEB: `CFLAGS=CXXFLAGS=-Wno-error=free-nonheap-object -Wno-error=implicit-function-declaration` | same two flags plus `-ffile-prefix-map=<workspace>=.`; per-object `-frandom-seed=<output path>` added by the compiler/linker launcher; `LDFLAGS=-flto-partition=balanced` (GCC's default, made explicit) `-ffile-prefix-map=<workspace>=.` (the LTO link writes the debug info); `SOURCE_DATE_EPOCH` exported | Bit-for-bit reproducible apks with LTO on (spec section 9). Non-semantic. Spec section 5 CMake flags are used verbatim; nothing in that list was changed. |
| PS compiler flags baseline (percona-server) | DEB rules export CFLAGS outright (no distro hardening); the official image's RPM build has redhat-rpm-config hardening | melange's default CFLAGS/CXXFLAGS/CPPFLAGS/LDFLAGS replaced by the DEB flags + shared baseline `hardening_cflags` (`-U_FORTIFY_SOURCE -D_FORTIFY_SOURCE=2 -fstack-protector-strong -fstack-clash-protection -fcf-protection -Wformat -Werror=format-security`) / `hardening_ldflags` (`-Wl,-z,relro -Wl,-z,now`) from versions/9.7.yaml + the reproducibility flags; -O/-g from `CMAKE_BUILD_TYPE`; LDFLAGS also reach the LTO links (`CMAKE_*_LINKER_FLAGS`) | Owner ruling R7: the official images are RHEL rpms built with redhat-rpm-config hardening and this is a production/public image; one key for all three compiled recipes so they cannot drift. Recipes check the flags reached CMakeCache; `melange test` checks GNU_RELRO, BIND_NOW and `__stack_chk_fail` in shipped binaries. Not added: `_FORTIFY_SOURCE=3`, `_GLIBCXX_ASSERTIONS`, `-march` (melange defaults; behaviour-changing). The recipes call `/usr/bin/gcc`/`/usr/bin/g++` directly: Wolfi's `build-base` puts openssf wrappers first in PATH (`/usr/local/bin`, `-specs openssf.spec`: `_GLIBCXX_ASSERTIONS`, `-fno-strict-aliasing`, `-fno-strict-overflow`, frame pointers, `--as-needed`), which would add exactly these behaviour-changing flags (and they break under ccache). v8 and mecab keep Wolfi's default (wrapped) compilers. MySQL's own `WITH_PACKAGE_FLAGS` stays off (no clash on `_FORTIFY_SOURCE`). |
| PS zlib (percona-server) | RPM: bundled zlib (`version_compile_zlib` 1.3.2) | Wolfi system zlib (`-DWITH_ZLIB=system`; `version_compile_zlib` reports `1.3.2.1-motley`, Wolfi's zlib version string) | Security fixes for zlib come with Wolfi updates instead of a PS rebuild; same zlib API/format. Allowlisted in tests/compat/allowlist.yaml (owner approval 2026-11-16). |
| PS install layout (percona-server) | RPM: real files in `/usr/sbin`, `/usr/lib64/mysql`, `/var/run/mysqld` | Configured with the RPM paths (`INSTALL_LAYOUT=RPM`, `lib64/mysql`, `share/percona-server`, socket `/var/lib/mysql/mysql.sock`) so compiled-in defaults match; files shipped under `/usr/bin` and `/usr/lib/mysql` | Wolfi's merged `/usr`: `/usr/sbin`→`bin`, `/usr/lib64`→`lib`, `/var/run`→`../run` are symlinks owned by wolfi-baselayout. Every RPM path resolves at runtime. |
| PS client library name (percona-server) | RPM ships `libmysqlclient.so.24*`, `libmysqlclient.a`, `mysqlclient.pc` (renamed by Percona's RPM packaging) | upstream CMake name `libperconaserverclient.so.24*` (as DEB), plus `libmysqlclient.so.24`, `libmysqlclient.so`, `libmysqlclient.a`, `mysqlclient.pc` symlinks | No source edits; both names link. |
| PS MeCab (percona-server) | RPM bundles MeCab + ipadic under `/usr/lib64/mysql/mecab` | `WITH_MECAB=system` (DEB/spec) with the `mecab`/`mecab-ipadic` apks; `/usr/lib64/mysql/mecab/etc/mecabrc` and `.../mecab/dic` are symlinks to `/etc/mecabrc` and `/usr/lib/mecab/dic` | Spec section 5. |
| PS debug build (percona-server) | RPM/DEB also build a `CMAKE_BUILD_TYPE=Debug` tree (`mysqld-debug`, `plugin/debug/`) | not built | Spec non-goal (no debug-build image); halves build time. |
| PS router (percona-server) | RPM/DEB package MySQL Router (`percona-mysql-router`) | Router is built (default flags, spec list unchanged) but removed from the install tree | Router is out of scope (spec section 3). |
| PS JS component packaging (percona-server) | RPM: `component_js_lang.so` in `percona-server-js`, which the official image does **not** install | same split: `percona-server-js` subpackage, **installed in both `percona-server:9.7` and `:9.7-dev`** | Keeps RPM parity at package level; owner ruling: JS stored programs (spec goal 2) ship in both server images. Allowlisted compat difference vs the official image (extra `component_js_lang.so`; the component is not loaded unless `INSTALL COMPONENT` is run). |
| PS scripts packaging (percona-server) | RPM: `mysqld_safe`, `mysqld_multi`, `mysqldumpslow`, `ps-admin` (and any other `#!` file) are in `percona-server-server` | same paths (`/usr/bin/...`, man pages), but in the subpackage `percona-server-scripts`, installed in the `-dev` image only (the distroless image has none of them); `percona-server-test` depends on it | melange adds a `cmd:<interpreter>` dependency for every `#!` file, which would pull sh/bash/perl (busybox) into the distroless image; `packages/percona-server/no-cmd-deps` + `scripts/check-no-cmd-deps.sh` keep the distroless subpackages free of them. |
